A deployment is a build of your site. Velu builds your content, deploys it, and
serves it from your domain. The **Activity** table on the
[dashboard Overview](/docs/dashboard/overview) page lists your deployments and their
status.

<Image src="/docs/images/dashboard/overview.png" alt="The dashboard Activity table listing deployments with their status and changes" />

## What triggers a build

A new deployment starts when:

- You push to the default branch `main` (docs-as-code mode).
- You click **Rebuild** on the [dashboard Overview](/docs/dashboard/overview) page.
- You **Publish** from the [web editor](/docs/dashboard/editor).
- Your site is first set up during onboarding.
- You add or change a [custom domain](/docs/deploy/custom-domains).
- You call [Trigger deployment](/docs/api-reference/introduction) on the REST API.
- You use [Instant Rollback](/docs/dashboard/rollback) to revert to an earlier build (Enterprise).
- You click **Promote latest** to restore the most recent build after a rollback (Enterprise).

## Build status

Each row in the Activity table shows one of these statuses:

| Status | Meaning |
| --- | --- |
| **Queued** | The build is waiting to start. |
| **Building** | The build is running. |
| **Successful** | The build finished and the site is live. |
| **Failed** | The build didn't finish. |
| **Live** | This build is currently serving production. Shown when a rollback is active. |
| **Completed** | A rollback or promote action finished successfully. |

The dashboard polls for status while a build runs, so the Overview page and
Activity table update on their own: you don't need to refresh. A build
typically takes about a minute.

## Failed builds

When a build fails, the row shows a **View build error** link with the build
log so you can find the cause. Velu also emails the site owner so a failure
doesn't go unnoticed.

<Callout type="tip">
  Preview your changes with `velu dev` before you publish. The dev server shows
  compile errors, unknown components, and bad props inline, so you can fix them
  before they reach a build.
</Callout>

## Rollback and promote

On the [Enterprise plan](/docs/dashboard/billing), you can revert your live site
to an earlier successful build using [Instant Rollback](/docs/dashboard/rollback),
or restore the latest build with **Promote latest**. These actions appear in
the Activity table with a **Completed** status and a `rollback` or `promote`
trigger label.
