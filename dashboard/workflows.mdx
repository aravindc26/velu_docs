Workflows are AI automations that keep your docs current by opening pull
requests. They live under **Agents › Workflows** at `/workflows`. Because they
open pull requests, they require docs-as-code mode with a connected GitHub repo,
and they're available on the Value plan.

<Image src="/docs/images/dashboard/workflows.png" alt="The Workflows page, showing the Value-plan upgrade prompt for docs automations" />

<Callout type="info">
  Workflows need the **Value** plan and a connected GitHub repository. In
  editor-only mode there's no repo to open pull requests against. See
  [Billing](/docs/dashboard/billing).
</Callout>

## How workflows work

A workflow runs on a trigger, inspects your docs, and (when it has a change to propose) opens a pull request. You review the pull request in GitHub and merge
it like any other, so nothing changes without your approval.

## Templates

Velu ships templates for common docs upkeep:

- **Changelog generation**: draft changelog entries from merged changes.
- **API-doc sync**: update reference docs when your API changes.
- **Translations**: keep translated pages in sync with the source.
- **Style-guide enforcement**: flag and fix wording that breaks your style
  guide.
- **Typo check**: catch spelling and grammar mistakes.
- **Broken-link detection**: find links that no longer resolve.
- **SEO audit**: check pages for missing titles, descriptions, and metadata.

## Triggers

Each workflow runs either:

- **On pull-request merge**: after a pull request lands on your default branch.
- **On a schedule**: at a recurring time you set.

## Run history

The run history table below the workflow list shows every run with its status,
trigger, source repository, and a link to the output pull request.

### Export to CSV

Use the **Export CSV** button in the run history toolbar to download a CSV file
of all runs matching your current filters. The file is named
`velu-workflow-runs-YYYY-MM-DD.csv` and opens correctly in spreadsheet tools
such as Excel, Google Sheets, and Numbers.

Each row contains:

| Column | Description |
| --- | --- |
| Run ID | Unique numeric identifier for the run |
| Workflow | Workflow name |
| Status | `completed`, `skipped`, `failed`, or `running` |
| Trigger | What triggered the run (`on_pr_merge` or a schedule) |
| Repository | The source repository that triggered the run |
| PR Number | Pull request number that triggered the run |
| PR Title | Pull request title that triggered the run |
| Started At | ISO 8601 timestamp of when the run started |
| Completed At | ISO 8601 timestamp of when the run finished |
| Summary | Short summary produced by the workflow |
| Output PR | Link to the pull request the workflow opened in your docs repo |

The export respects both the **workflow selector** and the **status filter**
active at the time you click the button. To export all runs across all
workflows, make sure "All workflows" and "All statuses" are selected. To narrow
the export to a single workflow or status (e.g. only `skipped` runs), select the
appropriate filters first.

<Callout type="note">
  The Export CSV button is disabled while run history is loading or while a
  previous export is in progress.
</Callout>

## Cost

Each workflow run costs 14 credits, drawn from your plan's monthly allotment or
purchased balance. See [Billing](/docs/dashboard/billing) for credits and top-ups.
